### I never wanted to learn how to code... 
I was always very happy in front of a UI. Tried to stay as far away from terminals as possible. Then I started working with Ubuntu, and that was the start of using terminals for everything. Still not code, but one step closer. As time went on and I got further through my career code became an inevitability if I wanted to become more senior and get more experience. This started out with simple bash scripting, which was mostly just further terminal commands, then I needed to start automating things, which leads futher down the rabbithole into loops and conditionals. 

Soon after I was creating scripts to output values for monitoring Macs through Extension Attributes in Jamf, leading to more complicated scripts and loops, bolstered by me taking the Jamf 200 course with an official scripting section (although basic). From there I've delved into Python and a small amount of Go for a few key utitilities and tools. But I needed to be creating things more often if I were to learn more. This has led to some of the work I've been doing recently on the Gaggimate project.

### Bring your work into your hobbies! 
That's the key. If you're wanting to learn something, it makes it a little easier to stay focused on it if you are actively interested in the result. I wanted to add a bit more observability into my coffee machine (which I had already modded with the 'Gaggimate Pro' hardware and firmware) and rather than wait for someone else to do it, I set about learning a bit more about C++ in order to get this job done.
